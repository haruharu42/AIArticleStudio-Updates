# Phase 3.5-B4 Acceptance Tests

## 1. 目的

有料記事・特典価値エンジンが、文字数水増し・架空実績・特典の名目だけ追加といった失敗を起こさず、B5回答取り込みへ正しい期待値を渡せることを確認する。

## 2. 必須テストケース

### T01 無料記事

入力:
- free_paid = free

期待:
- PaidValueProfile.enabled = false
- paid / bonus UIは非表示
- paid boundaryを要求しない

### T02 AI副業・低価格

期待:
- 実践手順を含む
- copy_paste_prompt / checklist / template のいずれかを優先
- 特典推奨数は1
- 架空収益を要求しない

### T03 AI副業・高価格

期待:
- 高価格だから文字数だけ増やさない
- 成果物2〜3個を上限として提案
- roadmap / template / decision framework 等で価値差を作る

### T04 ガジェット

期待:
- comparison / decision_framework / checklist を優先
- 未確認の価格・在庫・評価・レビューを生成要件にしない

### T05 キャリア

期待:
- worksheet / checklist を優先
- 転職成功・内定を保証しない

### T06 学習

期待:
- roadmap / worksheet / checklist を優先
- 合格保証をしない

### T07 本文との重複

入力:
- 本文成果物に checklist がすでに存在

期待:
- 特典候補で同一checklistを避ける
- 代替としてtemplate / worksheet等を選べる

### T08 ユーザー実体験なし

期待:
- primary_experience を必須成果物にしない
- 「私が実際に〜」を要求しない

### T09 ユーザー実体験あり

期待:
- 入力された範囲内で体験を活用可能
- 不足部分を補完して実績を創作しない

### T10 有料境界

期待:
- 無料部分に最低限の価値がある
- 境界直前で「ここから先の追加価値」を説明
- 煽り・恐怖・虚偽の希少性に依存しない

### T11 特典完成性

期待:
- 「チェックリスト付き」とだけ書かない
- 実際のチェック項目本文が生成要件に含まれる

### T12 price_fit thin

入力:
- 高価格
- 成果物なし / 実践性なし

期待:
- price_fit = thin
- missing_value_elements が1件以上
- 公開準備完了扱いにしない

### T13 price_fit overbuilt

入力:
- 低価格
- 大量の独立成果物 / 長大な複数テーマ

期待:
- price_fit = overbuilt を許容
- シリーズ分割候補を提案可能

### T14 B5契約

期待:
B4の出力からB5が少なくとも以下を検出対象として受け取れる。
- paid_boundary_detected
- bonus_headings
- actionable_outputs_detected
- summary_detected
- cta_detected

## 3. 禁止パターンテスト

以下が生成要件に混入した場合は失敗扱い。

- 「必ず稼げます」
- 「100%成功」
- ユーザー未入力の売上・PV・購入数
- ユーザー未入力の使用体験
- 未確認の商品価格
- 未確認の星評価 / レビュー数
- 架空の期間限定キャンペーン
- 特典名だけあり中身なし
- 無料部分がほぼ宣伝だけ

## 4. 合格基準

- T01〜T14がすべて合格
- 禁止パターンが0件
- 同一条件で再実行しても成果物候補数が上限3を超えない
- 既存本文を壊さずB4単体で再評価できる

## 5. 実装担当への注意

B4は記事本文そのものを直接書き換える責務を持たない。

責務は以下。
- 有料価値の設計
- 必要成果物の決定
- 特典候補の決定
- 価格適合判定
- 警告生成
- プロンプトへ渡す契約生成

実際のWeb AI出力に要件が反映されたかの検査はB5/B6が担当する。
