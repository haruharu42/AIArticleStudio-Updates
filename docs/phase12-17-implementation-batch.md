# Phase 12–17 一括機能実装

基準: Phase 9–11 commit `f2bbbe8840b99bc17e40e62166c48b72fab18b04`

このバッチは細かなUI調整より先に、AASを記事作成から画像計画・SNS・公開管理・内部分析まで一続きで使える状態へ拡張するソース実装です。Phase 6–8の認証、記事、画像、RLS、利用権を置き換えず再利用します。

## Phase 12 — 記事プロンプト専門化

- 掲載先: note / Tips / Brain / ブログ
- 記事タイプ: 無料 / 有料
- ジャンル別: AI副業、生成AI、美容、ガジェット、生活・暮らし、SNS等
- 実践手順、比較軸、チェックリスト、テンプレートなどジャンルごとの成果物候補を記事プロンプトへ追加
- 実体験・実績の創作、未確認価格・仕様・統計の断定、成果保証、競合コピーを禁止

Phase 11の記事作成プロンプトへ統合し、`workspace_json.prompt_profile_version = 12`を保存します。

## Phase 13 — 画像生成計画

- アイキャッチと挿絵のプロンプトを同一記事条件から生成
- 日本の現代的な2Dアニメ調をAASの共通基準として使用
- 挿絵は`<!-- IMAGE:01 -->`等の本文マーカーと対応
- 既存作品・特定作家・実在人物・ブランドロゴ等の模倣を避ける
- `/images`で既存記事から画像プロンプトを再生成可能
- Phase 11保存時は`image_plan_json.prompt_plan`へ保存

このPhaseでは画像生成APIをブラウザーから直接呼びません。実画像生成は秘密鍵を保持するサーバー実行層が決まってから接続します。

## Phase 14 — SNS投稿作成

`/sns`で共通記事ライブラリの記事を選び、X / Instagram / Threads用の投稿生成プロンプトへ変換します。

- 記事への導線
- 交流・反応
- 有料コンテンツへの関心
- トーン、編集上の文字数目安、ハッシュタグ有無

元記事にない体験・成果・数字を追加しない編集ルールを維持します。SNS APIへの直接投稿はまだ行いません。

## Phase 15 — AI副業プランナー

`/sidejob`で作業時間、顔出し、予算、文章/画像/動画/営業の得意度、経験、目標を入力し、AAS内の比較ロジックで候補を順位付けします。

候補にはコンテンツ販売、アフィリエイト、デジタル商品、SNS運用、ショート動画、YouTube/TikTok/配信、AI記事制作支援を含みます。

適合スコアはAAS内の比較値であり、収益・成功率・市場順位ではありません。30日プランはChatGPT用プロンプトとして書き出します。

## Phase 16 — 公開管理

`/publish`で既存記事の次の状態を管理します。

- 完成
- 公開待ち + 公開予定日時
- 公開済み + 公開日時 + 公開URL

保存は既存`update_article_with_workspace`を使い、記事revision競合を維持します。外部サービスへの自動投稿はOAuth/API接続後の工程です。

## Phase 17 — 内部コンテンツ分析

`/analytics`で既存`get_my_article_stock_summary()`と記事一覧を使い、次を表示します。

- 記事ストック数 / 上限 / 残数
- 公開済み数と記事ストック内比率
- 完成 + 公開待ち
- 下書き + 執筆中
- 掲載先別件数
- 状態別件数
- 最近更新した記事

閲覧数、売上、SNS反応など外部サービスの実績値は、正式なデータ連携がない段階では表示しません。

## 共通導線

`/tools`を機能ハブとして追加し、ログイン・利用権・管理者状態に応じて利用可能な画面だけを案内します。既存ホームにはクイックナビを残し、Phase 8の記事ライブラリと画像同期を置換しません。

## このバッチ後も外部仕様待ちの機能

- 決済サービスWebhookによる自動利用権付与
- OpenAI等の秘密鍵を保持するサーバー側AI実行
- AI画像生成APIの直接実行とPhase 8 Storageへの自動保存
- X / Instagram / ThreadsへのOAuth投稿
- note / Tips / Brainへの自動投稿
- 外部の閲覧数・売上・SNS分析値の取得

これらはブラウザーへ秘密鍵を埋め込まず、各サービスの正式API・OAuth・販売チャネル仕様を決定してから実装します。

## 検証ゲート

実装後にまとめて、TypeScript、ESLint、PWA build、Phase 6–17テスト、npm audit、SQL/RLS、使い捨てデータによる実E2Eを行います。検証が終わるまで`main`、本番Supabase、release/updater/latest.jsonは変更しません。
