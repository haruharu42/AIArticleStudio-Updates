# Phase 9–11 一括実装境界

基準commit: `ce26447c2eede5d2438ffa8399760f7960487c0a`

このバッチは、Phase 8で完成した認証・利用権・共通記事・共通画像の基盤を壊さず、PWAを「閲覧/編集中心」から「利用開始・管理・新規制作」まで進めるためのソース実装です。細かなUI調整より先に、機能の縦断経路を通します。

## Phase 9 — PWA招待/利用開始

### 実装

- active管理者がPWA招待コードを作成・一覧・無効化できる。
- 招待コードに販売チャネル、外部参照、コード期限、利用回数、付与利用権期限を保持できる。
- pending/activeの一般ユーザーは、既存PWA利用権がなくても`/invite`からコードを登録できる。
- 正常なコードは`AAS-PWA-BETA`利用権へ変換する。
- 同じ招待/同じユーザーの二重利用を拒否し、利用履歴を監査テーブルへ保存する。
- 招待テーブルと履歴テーブルは直接DMLを配布クライアントへ許可しない。

### このバッチで未実施

- note/Tips/Brain等の決済サービスからの自動Webhook付与。
- メールへの招待コード自動送信。
- 本番Supabaseへのmigration適用。

外部決済の正式仕様が決まるまでは、販売チャネルと外部参照を共通フィールドとして保持し、管理者が手動発行できる形を先行実装する。

## Phase 10 — 共通管理ダッシュボード

### 実装

`/admin`をactive adminだけに公開する。

- ユーザー一覧、AAS ID検索。
- pending → active承認。
- active → suspended停止。
- suspended → active再開。
- ログイン中管理者の自己停止をUIでも抑止し、DB側の既存防御も維持。
- 一般ユーザーのWindows/PWA利用権履歴を表示。
- `AAS-WIN-BETA` / `AAS-PWA-BETA`の付与・取消。
- 販売チャネル、外部参照、利用期限の入力。
- PWA招待コード作成・一覧・無効化。

メールアドレスは既存仕様どおり管理一覧へ表示しない。

### このバッチで未実施

- 売上ダッシュボード。
- 決済API同期。
- 詳細な監査ログ画面。
- 管理画面の最終デザイン調整。

## Phase 11 — PWA記事制作フロー

### 実装

`/create`で次の7ステップを実装する。

1. 生成方法
2. 画像計画
3. 本文条件
4. タイトル
5. 本文生成
6. プレビュー
7. 保存

条件には掲載先、無料/有料、ジャンル、サブジャンル、対象年齢、対象性別、文字数目安、価格、アフィリエイト、マガジン、タグ、アイキャッチ、挿絵枚数を含む。

生成方法はこの段階では次の2つ。

- ChatGPTプロンプト書き出し
- 手動作成

プロンプト書き出しは、掲載先/無料有料/読者/画像計画を反映し、以下の保護ルールを常に含む。

- 入力されていない実体験・実績・レビューを創作しない。
- 未確認の価格・在庫・評価・ランキング・統計等を断定しない。
- 競合記事をコピー・近似模倣しない。
- 成果保証・過度な煽り・架空の権威づけをしない。
- 架空例は例/想定と明記する。

保存時は既存`create_article_with_workspace`を利用し、記事本体と次のWorkspace情報を同時保存する。

- request_json: 入力条件
- workspace_json: ウィザード/選択状態
- image_plan_json: アイキャッチ/挿絵計画
- source_body
- publish_body

記事上限は既存`create_article`のサーバー側クォータをそのまま利用する。所有者IDは認証ユーザーと一致することを応答でも検査する。

### このバッチで未実施

- OpenAI等のAPIをPWAから直接呼ぶ生成処理。
- モデルルーティング・利用量・ユーザー別API課金。
- AI画像の直接生成。
- note/Tips/Brainへの自動投稿。

これらは秘密鍵をブラウザーへ置かないサーバー実行層を設計してから追加する。

## 既存Phase 6–8の保護

このバッチでは既存の大きな`Phase7App`と記事ライブラリ/画像管理を置換しない。ルート`/`は既存シェルを維持し、ログイン状態に応じたクイック導線だけを追加する。

これにより、Phase 6 Auth/PKCE、Phase 7ライブラリ、Phase 8画像管理の回帰範囲を小さくする。統合ナビゲーションやPhase表示更新は、機能縦断テスト後のUI仕上げで実施する。
