# AAS 全機能管理センター

AASのコード配布と機能公開を分離して管理するための運用仕様です。

## 公開段階

ユーザー向け機能は次の3段階で管理します。

1. 管理者のみ
2. 指定した一般ユーザーテスター（既定: AAS-000002）
3. 全一般ユーザー

管理者専用機能はDB制約と管理RPCの両方で「管理者のみ」に固定し、一般ユーザーへ公開できません。

## メンテナンスモード

ユーザー向け機能ごとにメンテナンスモードをON/OFFできます。

- 管理者: 常時利用可能
- 指定テスター: rollout_stage が tester/public なら利用可能
- 通常の一般ユーザー: 利用不可
- メンテナンス案内文: 機能単位で設定可能

これにより、不具合発生時に全アプリを止めず対象機能だけ停止し、AAS-000002で修正後の確認を行ってから全体へ戻せます。

## 管理画面

管理ダッシュボード → 全機能管理センター

カテゴリは通常閉じた状態の details UI で表示し、必要なカテゴリだけ展開します。

各ユーザー向け機能には以下を表示します。

- 現在の公開段階
- 管理者のみ
- AAS-000002等でテスト
- 全一般ユーザー
- メンテナンスモード
- ユーザー向け案内文
- 最終変更日時 / 変更管理者

## 安全設計

- app_feature_controls と監査テーブルは RLS + FORCE RLS。
- anon/authenticated のテーブル直接アクセスを撤回。
- ユーザーの利用可否は SECURITY DEFINER RPC からのみ取得。
- 管理変更RPCは private.is_active_admin() を再確認。
- private.can_use_app_feature はブラウザ authenticated から実行不可。
- /admin/features, /admin/releases, /admin/operations は緊急復旧用の管理経路としてFeature Gateから除外。
- ログイン、ログアウト、認証コールバック、利用規約、プライバシー等の基盤ページは機能停止対象にしない。

## 登録済み

初期登録:
- ユーザー向け 36機能
- 管理者向け 16機能
- 合計 52機能

記事作成、記事ライブラリ、プロンプト、画像、SNS、ワークフロー、note運営、公開、分析、プロフィール、ランキング、会員機能、12種類の副業ウィザード、通知管理、各管理者ツールを対象にしています。

記事ライブラリは独立Routeではなくホーム内埋め込みのため、専用hookでも同じFeature Controlを確認します。

## リリース管理との関係

- アップデート管理: コード/バージョンの3段階配信
- 全機能管理センター: 実装済み機能の公開範囲・メンテナンス

コードをPreviewへ置いた後も、機能単位では「管理者のみ」のまま保持できます。
